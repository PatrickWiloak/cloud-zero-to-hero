# Learning Paths Across the Four Zero to Hero Sites

**In one line:** Seven short routes that cross cloud, data, security and AI, each a handful of pages in a sensible order, with a reason for every step and the certifications that match.
**Last reviewed:** 2026-11-07

---

## How to use these paths

Real jobs do not stay inside one subject. A cloud engineer ends up owning IAM policy. A data engineer is asked to feed a model. A security engineer is handed an LLM agent to review. Each path below starts from a job you might have today and walks through pages on whichever site teaches the next skill.

- Every step is one existing page. Read it, try what it describes, then move on. You do not need to finish a whole site first.
- Each step says why it sits where it does, so you can skip one you already know.
- The certifications at the end are optional. They are the exams that line up with the path, not a required finish line.
- Not sure these are the right sites for you? [Which site should I start with?](https://cloud.noblerworks.com/learn/which-site/) compares all four.

| Path | You start as | You finish able to |
|---|---|---|
| [1. Zero to first cloud job](#1-zero-to-first-cloud-job) | Someone new to tech | Build and explain a small cloud system |
| [2. Cloud engineer who needs security](#2-cloud-engineer-who-needs-security) | A cloud or DevOps engineer | Lock down accounts, identities and secrets |
| [3. Data engineer moving into ML](#3-data-engineer-moving-into-ml) | A data engineer | Prepare features and ship a model |
| [4. Security engineer for AI systems](#4-security-engineer-for-ai-systems) | A security engineer | Threat model and test an LLM application |
| [5. Analyst to analytics engineer](#5-analyst-to-analytics-engineer) | A spreadsheet or BI analyst | Own a tested, modeled warehouse layer |
| [6. AI engineer who deploys](#6-ai-engineer-who-deploys) | A developer building AI apps | Run an AI app in production |
| [7. Cloud engineer who runs data platforms](#7-cloud-engineer-who-runs-data-platforms) | A cloud engineer | Stand up and govern a lakehouse |

## 1. Zero to first cloud job

For someone who has never opened a terminal and wants a junior cloud role.

1. **[Terminal basics](https://cloud.noblerworks.com/learn/day-one/terminal-basics/)** (Cloud) - every cloud task eventually happens in a shell, so this comes first.
2. **[What is a server?](https://cloud.noblerworks.com/learn/day-one/what-is-a-server/)** (Cloud) - cloud is rented servers, so you need a clear picture of one before the rest makes sense.
3. **[What is cloud computing?](https://cloud.noblerworks.com/learn/concepts/what-is-cloud-computing/)** (Cloud) - the vocabulary: regions, services, pay-as-you-go.
4. **[Cloud from Scratch](https://cloud.noblerworks.com/learn/cloud-from-scratch/)** (Cloud) - the full path through compute, storage, networking, identity and containers.
5. **[IAM explained](https://security.noblerworks.com/learn/concepts/iam-explained/)** (Security) - identity is the first thing every cloud team asks a new hire about, and Security teaches it in depth.
6. **[Deploy a 3-tier app](https://cloud.noblerworks.com/resources/hands-on-projects/deploy-3-tier-app/)** (Cloud) - a build you can show an interviewer.
7. **[Cloud engineer interview prep](https://cloud.noblerworks.com/resources/interview-prep/cloud-engineer-interview/)** (Cloud) - the questions to practice once you have built something.

**Matching certifications:** [AWS Cloud Practitioner](https://cloud.noblerworks.com/exams/aws/foundational/cloud-practitioner-clf-c02/), then [AWS Solutions Architect Associate](https://cloud.noblerworks.com/exams/aws/associate/solutions-architect-saa-c03/) or [Azure AZ-104](https://cloud.noblerworks.com/exams/azure/az-104/). The [cloud engineer roadmap](https://cloud.noblerworks.com/resources/certification-roadmap-cloud-engineer/) puts them in order.

## 2. Cloud engineer who needs security

For someone who already deploys to the cloud and is now answerable for how safely.

1. **[Shared responsibility model](https://security.noblerworks.com/learn/concepts/shared-responsibility-model/)** (Security) - what the provider secures and what is left to you.
2. **[IAM explained](https://security.noblerworks.com/learn/concepts/iam-explained/)** (Security) - users, roles and policies, the root of most cloud breaches.
3. **[Least privilege](https://security.noblerworks.com/learn/concepts/least-privilege-explained/)** (Security) - how to shrink permissions without breaking deployments.
4. **[Secrets management](https://security.noblerworks.com/learn/concepts/secrets-management/)** (Security) - where keys and tokens live once they are out of your code.
5. **[Multi-account and landing zones](https://cloud.noblerworks.com/learn/concepts/multi-account-and-landing-zones/)** (Cloud) - the account structure that makes guardrails enforceable.
6. **[CSPM and CNAPP explained](https://security.noblerworks.com/learn/concepts/cspm-and-cnapp-explained/)** (Security) - tools that find misconfigurations across your accounts.
7. **[Least-privilege IAM review](https://security.noblerworks.com/resources/hands-on-projects/least-privilege-iam-review/)** (Security) - audit a real account and fix what you find.
8. **[Cloud security engineer roadmap](https://security.noblerworks.com/resources/certification-roadmap-cloud-security-engineer/)** (Security) - the career route this path opens.

**Matching certifications:** [CompTIA Security+](https://security.noblerworks.com/exams/comptia/security-plus/), [AWS Security Specialty (SCS-C03)](https://security.noblerworks.com/exams/aws/specialty/security-scs-c03/) and [CCSK](https://security.noblerworks.com/exams/cloud-security-alliance/ccsk/).

## 3. Data engineer moving into ML

For someone who builds pipelines and now wants to train, serve and monitor models.

1. **[Data pipelines and orchestration](https://data.noblerworks.com/learn/concepts/data-pipelines-and-orchestration/)** (Data) - the skill you already have, restated as the base ML pipelines are built on.
2. **[What is machine learning?](https://ai.noblerworks.com/learn/concepts/what-is-machine-learning/)** (AI) - the vocabulary of features, labels and models.
3. **[Training, validation and overfitting](https://ai.noblerworks.com/learn/concepts/training-validation-and-overfitting/)** (AI) - why data splits matter and how leakage ruins results.
4. **[Feature engineering and data prep](https://ai.noblerworks.com/learn/concepts/feature-engineering-and-data-prep/)** (AI) - where a data engineer's strengths count most.
5. **[Feature stores for data engineers](https://data.noblerworks.com/learn/concepts/feature-stores-for-data-engineers/)** (Data) - serving the same features in training and in production.
6. **[Tabular ML end to end](https://ai.noblerworks.com/build/projects/tabular-ml-end-to-end/)** (AI) - one full build from raw table to evaluated model.
7. **[Deploy an ML model](https://ai.noblerworks.com/build/projects/deploy-ml-model/)** (AI) - getting it behind an endpoint.
8. **[ML Engineer Path](https://ai.noblerworks.com/learn/start-here/ml-engineer-path/)** (AI) - the longer road once the first model ships.

**Matching certifications:** [AWS Machine Learning Engineer Associate](https://ai.noblerworks.com/certifications/aws/associate/ml-engineer-mla-c01/), [Google Professional Machine Learning Engineer](https://ai.noblerworks.com/certifications/gcp/machine-learning-engineer/) and [Databricks ML Associate](https://ai.noblerworks.com/certifications/databricks/ml-associate/).

## 4. Security engineer for AI systems

For someone who knows threat modeling and now has to review an LLM feature or agent.

1. **[LLM basics](https://ai.noblerworks.com/learn/concepts/llm-basics/)** (AI) - you cannot threat model what you cannot describe: tokens, context, tools.
2. **[Threat modeling explained](https://security.noblerworks.com/learn/concepts/threat-modeling-explained/)** (Security) - the method you will reuse in step 4.
3. **[Prompt injection explained](https://ai.noblerworks.com/safety/security/prompt-injection-explained/)** (AI) - the attack with no equivalent in classic application security.
4. **[AI threat modeling](https://ai.noblerworks.com/safety/security/ai-threat-modeling/)** (AI) - applying the method to models, data and tools.
5. **[OWASP LLM Top 10](https://ai.noblerworks.com/safety/security/owasp-llm-top-10/)** (AI) - the checklist reviewers expect to see.
6. **[Agent security](https://ai.noblerworks.com/safety/security/agent-security/)** (AI) - what changes when the model can act.
7. **[LLM red teaming](https://ai.noblerworks.com/safety/security/llm-red-teaming/)** (AI) - how to test rather than guess.
8. **[Secrets management](https://security.noblerworks.com/learn/concepts/secrets-management/)** (Security) - agents hold credentials, so apply the classic controls to them.

**Matching certifications:** [CompTIA Security+](https://security.noblerworks.com/exams/comptia/security-plus/) as the base, then [IAPP AIGP](https://security.noblerworks.com/exams/iapp/aigp/), [ISACA AAISM](https://security.noblerworks.com/exams/isaca/aaism/) and [CSA TAISE](https://security.noblerworks.com/exams/cloud-security-alliance/taise/).

## 5. Analyst to analytics engineer

For someone fluent in spreadsheets or BI tools who wants to own the modeled layer under the dashboards.

1. **[Spreadsheets to SQL](https://data.noblerworks.com/learn/day-one/spreadsheets-to-sql/)** (Data) - the bridge from the tool you know.
2. **[SQL joins explained](https://data.noblerworks.com/learn/concepts/sql-joins-explained/)** (Data) - the most common source of wrong numbers.
3. **[Window functions](https://data.noblerworks.com/learn/concepts/window-functions-explained/)** (Data) - running totals, ranks and comparisons without self-joins.
4. **[Data modeling for analytics](https://data.noblerworks.com/learn/concepts/data-modeling-for-analytics/)** (Data) - facts, dimensions and star schemas.
5. **[Analytics engineering and dbt](https://data.noblerworks.com/learn/concepts/analytics-engineering-and-dbt/)** (Data) - models, tests and docs as code.
6. **[Build a dbt project](https://data.noblerworks.com/resources/hands-on-projects/build-dbt-project/)** (Data) - practice on a real project.
7. **[Git basics](https://cloud.noblerworks.com/learn/day-one/git-basics/)** (Cloud) - analytics engineering runs on pull requests and review.
8. **[Analytics engineer roadmap](https://data.noblerworks.com/resources/certification-roadmap-analytics-engineer/)** (Data) - where to go after the first dbt project.

**Matching certifications:** [Microsoft PL-300](https://data.noblerworks.com/exams/azure/pl-300/), [Databricks Data Analyst Associate](https://data.noblerworks.com/exams/databricks/data-analyst-associate/) and [SnowPro Core](https://data.noblerworks.com/exams/snowflake/snowpro-core/).

## 6. AI engineer who deploys

For a developer who has a working prototype and now has to run it for real users.

1. **[AI Engineer Path](https://ai.noblerworks.com/learn/start-here/ai-engineer-path/)** (AI) - the map of what you already know and what is missing.
2. **[Containers vs VMs](https://cloud.noblerworks.com/learn/concepts/containers-vs-vms/)** (Cloud) - how the app gets packaged.
3. **[CI/CD explained](https://cloud.noblerworks.com/learn/concepts/cicd-explained/)** (Cloud) - ship changes without surprises.
4. **[Infrastructure as code](https://cloud.noblerworks.com/learn/concepts/infrastructure-as-code-explained/)** (Cloud) - make the environment reproducible.
5. **[Secrets management](https://security.noblerworks.com/learn/concepts/secrets-management/)** (Security) - API keys for model providers are valuable; keep them out of images and repos.
6. **[LLMOps and observability](https://ai.noblerworks.com/build/patterns/llmops-observability/)** (AI) - traces, cost and quality signals in production.
7. **[Evals for LLMs](https://ai.noblerworks.com/learn/concepts/evals-for-llms/)** (AI) - the regression tests for a non-deterministic system.
8. **[Guardrails architecture](https://ai.noblerworks.com/build/patterns/guardrails-architecture/)** (AI) - the controls that sit around the model.

**Matching certifications:** [Azure AI-102](https://ai.noblerworks.com/certifications/azure/ai-102/), [HashiCorp Terraform Associate](https://cloud.noblerworks.com/exams/hashicorp/terraform-associate/) and [AWS Developer Associate](https://cloud.noblerworks.com/exams/aws/associate/developer-dva-c02/).

## 7. Cloud engineer who runs data platforms

For someone who provisions infrastructure and is now asked to host the warehouse or lakehouse.

1. **[Managed databases explained](https://cloud.noblerworks.com/learn/concepts/managed-databases-explained/)** (Cloud) - what the provider runs for you and what stays yours.
2. **[OLTP vs OLAP](https://data.noblerworks.com/learn/concepts/oltp-vs-olap/)** (Data) - why the application database and the analytics store differ.
3. **[Warehouses, lakes and lakehouses](https://data.noblerworks.com/learn/concepts/warehouses-lakes-lakehouses/)** (Data) - the three shapes of analytics storage.
4. **[ETL vs ELT](https://data.noblerworks.com/learn/concepts/etl-vs-elt/)** (Data) - where transformation runs and what that does to cost.
5. **[Medallion architecture](https://data.noblerworks.com/resources/architecture-patterns/medallion-architecture/)** (Data) - the bronze, silver and gold layout most platforms use.
6. **[Encryption explained](https://security.noblerworks.com/learn/concepts/encryption-explained/)** (Security) - keys and encryption at rest for the data you now hold.
7. **[Warehouse cost control](https://data.noblerworks.com/learn/concepts/warehouse-cost-control/)** (Data) - the bill is the first thing your team will ask about.
8. **[Backup and point-in-time restore](https://data.noblerworks.com/learn/concepts/backup-and-point-in-time-restore/)** (Data) - prove you can recover before you need to.

**Matching certifications:** [AWS Data Engineer Associate](https://data.noblerworks.com/exams/aws/associate/data-engineer-dea-c01/), [Google Professional Data Engineer](https://data.noblerworks.com/exams/gcp/data-engineer/) and [Azure DP-900](https://data.noblerworks.com/exams/azure/dp-900/).
